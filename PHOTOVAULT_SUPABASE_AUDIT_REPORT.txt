A. TỔNG QUAN PROJECT
================================================================================
1. Cấu trúc thực tế:
   - Module đơn (:app).
   - Package ứng dụng: com.example.th6
   - Mã nguồn ứng dụng kết hợp giữa Android Java (Activities, Fragments, Adapters, Views, Services) và Kotlin (Supabase Data Layer, Repositories, ViewModels, Models).

2. Stack công nghệ hiện tại:
   - Android Compile SDK: 36 | Target SDK: 35 | Min SDK: 24 | Java 11.
   - Kotlin Compiler Plugin: 2.4.21 (kotlinx.serialization plugin enabled).
   - Android Gradle Plugin (AGP): 9.3.3.
   - UI: XML Layouts + ViewBinding + Material Design Components 3.
   - Backend Cloud: Supabase Kotlin SDK v3.8.0
     + Supabase Auth (Auth v3 - Email/Password, Sessions).
     + Supabase Postgrest (Database Postgrest v3 - photos, albums, users tables).
     + Supabase Storage (Storage v3 - bucket: photos_bucket).
   - Network Transport: Ktor Client Android 3.6.0.
   - Serialization: KotlinX Serialization JSON 1.7.3.
   - Image Loading & Display: Glide 4.16.0 (Hỗ trợ URL công khai HTTP/HTTPS của Supabase Storage).
   - Video Engine: androidx.media3 (ExoPlayer, UI, Transformer 1.3.1).
   - Background Task Engine: WorkManager 2.9.0 + SQLite Ledger (`BackupUploadLedger.java`).

3. Kiến trúc tổng thể:
   - Event-driven / Controller Architecture với Activity + Fragment + Repositories + ViewModels + WorkManager Worker.
   - Layer dữ liệu chính:
     * `SupabaseManager.kt`: Singleton tập trung giữ instance `SupabaseClient` cho Auth, Postgrest, Storage.
     * `AuthRepository.kt`: Lớp đóng gói các thao tác Supabase Auth & Session management.
     * `PhotoRepository.kt`: Lớp đóng gói các thao tác CRUD bảng `photos`, `albums`, `users` qua Supabase Postgrest.
     * `StorageRepository.kt`: Lớp đóng gói upload, delete, public URL từ Supabase Storage `photos_bucket`.
     * `PhotoUploadViewModel.kt` & `PhotoDeleteViewModel.kt`: ViewModel xử lý luồng nghiệp vụ tải lên và xóa ảnh.

G. DANH SÁCH LỖI VÀ RỦI RO (ISSUES & RISKS)

[P1 — HIGH] AUDIT-P1-001: Tính năng Auto-Backup Nền Chưa Hỗ Trợ Sao Lưu Video
- Bằng chứng: `PhotoBackupWorker.java` (dòng 115): `if (local.isVideo()) continue;` và `PhotoBackupManager.java` (dòng 42): `if (!item.isVideo()) images.add(item);`.
- Điều kiện xảy ra: Khi người dùng bật tính năng Auto-Backup trong BackupCenterActivity.
- Hậu quả: Mặc dù giao diện thông báo "Sao lưu toàn bộ thư viện", hệ thống thực tế chỉ quét và upload ảnh tĩnh. Toàn bộ video local bị bỏ qua không được sao lưu lên Supabase Storage.
- Cách xác minh: Thêm video mới vào thiết bị, kích hoạt "Sao lưu ngay" và kiểm tra danh sách tệp được đẩy lên `photos_bucket`.
- Hướng sửa đề xuất: Cập nhật `PhotoBackupManager` và `PhotoBackupWorker` để hỗ trợ nạp và tải video MP4 lên Supabase Storage bucket (hoặc bucket riêng `videos_bucket`).

[P1 — HIGH] AUDIT-P1-002: Chuỗi Văn Bản Giao Diện Vẫn Còn Hiển Thị Tên Thương Hiệu Cũ (ImgBB)
- Bằng chứng: `res/layout/dialog_backup_onboarding.xml` (dòng 31), `res/layout/dialog_photo_info.xml` (dòng 65, 74), `res/values/strings.xml` (dòng 92).
- Điều kiện xảy ra: Khi người dùng bật dialog hướng dẫn Onboarding sao lưu hoặc mở xem thông tin ảnh (Photo Info BottomSheet).
- Hậu quả: Người dùng nhìn thấy thông tin "ImgBB Cloud Storage" thay vì "Supabase Cloud Storage", gây hiểu nhầm về hạ tầng lưu trữ.
- Cách xác minh: Mở ứng dụng lần đầu hoặc xem thông tin chi tiết một bức ảnh đã sao lưu.
- Hướng sửa đề xuất: Cập nhật lại các chuỗi string resource trong `strings.xml` và các file layout XML thay "ImgBB" thành "Supabase Cloud".

[P2 — MEDIUM] AUDIT-P2-001: Thiếu Realtime Listener Cho Dữ Liệu Cloud Gallery
- Bằng chứng: `PhotoRepository.kt` sử dụng `photosTable.select()` (REST HTTP query one-time) trong `getAllPhotos` và `getPhotosByUser`.
- Điều kiện xảy ra: Khi người dùng đăng nhập cùng 1 tài khoản trên 2 thiết bị A và B. Thiết bị A thêm/xóa ảnh hoặc album.
- Hậu quả: Màn hình trên thiết bị B không tự động cập nhật ngay lập tức mà yêu cầu người dùng phải thực hiện thao tác vuốt Vuốt để làm mới (SwipeRefresh) thủ công.
- Cách xác minh: Thêm một ảnh mới từ thiết bị A hoặc trên Supabase Dashboard và quan sát thiết bị B.
- Hướng sửa đề xuất: Tích hợp Supabase Realtime Channels hoặc `postgrest.from("photos").selectAsFlow()` trong `PhotoRepository` để phát hiện sự thay đổi thời gian thực.

[P2 — MEDIUM] AUDIT-P2-002: Tiêu Tốn Bộ Nhớ (OOM Risk) Khi Đọc Tệp Ảnh Lớn Để Upload
- Bằng chứng: `StorageRepository.kt` (dòng 72): `context.contentResolver.openInputStream(uri)?.use { it.readBytes() }`.
- Điều kiện xảy ra: Khi chọn upload hoặc sao lưu tệp ảnh có kích thước rất lớn (ví dụ: ảnh Panorama hoặc ảnh chụp chế độ 108MP dung lượng > 30MB).
- Hậu quả: Việc nạp toàn bộ ByteArray vào RAM một lúc có thể gây hiện tượng `OutOfMemoryError` trên các thiết bị cấu hình RAM thấp.
- Cách xác minh: Chọn upload tệp ảnh độ phân giải cực cao trên thiết bị RAM 2GB/3GB.
- Hướng sửa đề xuất: Sử dụng `UploadData.fromInputStream` hoặc stream nội dung tệp theo chuỗi chunk trong Supabase Storage SDK.

[P3 — LOW] AUDIT-P3-001: Thiếu Cơ Chế Phân Trang (Paging) Khi Danh Sách Ảnh Cloud Rất Lớn
- Bằng chứng: `PhotoRepository.kt` câu lệnh `photosTable.select().decodeList<Photo>()` lấy toàn bộ danh sách bản ghi không giới hạn LIMIT/OFFSET.
